# PIR — линейно-рекуррентная LM-архитектура PromeTorch

PIR — собственная архитектура языковой модели без attention: диагональный
selective scan, родственник Mamba / HGRN / RWKV. Спроектирована под
CPU-тренировку на Эльбрус E8C2 (VLIW): O(T) по времени и памяти вместо
O(T²) у attention, рекуррентность параллелится по каналам D — идеально
ложится на 6 FPU-каналов E2K и NUMA-топологию.

Практический гайд (сборка/данные/запуск): [examples/pir/README.md](../examples/pir/README.md).

## 1. Блок PIR — математика

Вход блока `x ∈ [B,T,D]`. Каждый TransformerBlock-аналог:

```
x ──RMSNorm₁──► s₀                            (поток PIR-стека)
для p = 0..NP-1:                              (NP суб-слоёв, обычно 4)
    g_p = s_p @ W_gate_pᵀ                     [B,T,D]
    v_p = s_p @ W_value_pᵀ                    [B,T,D]
    σ_p = sigmoid(g_p)
    промежуточный вход скана:  u_p = σ_p ⊙ v_p
    гейт скана:               a_p = σ_p ⊙ λ_p          (λ_p — base_decay, [D])
    скан:  h_t = a_t ⊙ h_{t-1} + u_t          (диагональная рекуррентность)
    o_p = RMSNorm_p(h @ W_out_pᵀ)
    s_{p+1} = s_p + o_p                       (residual внутри стека)
x = x + RMSNorm_mix(s_NP @ W_mixᵀ)            (выход PIR-блока в основной поток)
x = x + W₂·(silu(W₁·RMSNorm₂(x)) ⊙ W₃·RMSNorm₂(x))    (SwiGLU FFN)
```

Ключевые решения:

**Data-dependent гейт через сигмоиду.** `a_t = sigmoid(gate) ⊙ λ` —
селективность как у Mamba (что помнить/забывать решают данные), но без
проекций Δ/A/B/C: один гейт делит две роли — глубина затухания в скане
и амплитуда входа (`u = σ ⊙ v`). Backward учитывает оба пути градиента
через σ.

**Мульти-масштабный base_decay.** λ для суб-слоя p — linspace по каналам
в диапазоне, зависящем от p mod 4: (0.80–0.95), (0.95–0.99), (0.99–0.998),
(0.998–0.9995). Четыре временных шкалы: от «памяти на несколько токенов»
до «памяти на сотни токенов» — фиксированные, не тренируются (стабильность
на fp32 без спец-инициализации).

**Стек с накапливающимся residual.** Суб-слой p видит `s_p = norm1_out +
Σ_{k<p} o_k` — глубина внутри блока без роста параметров нормировок.

## 2. Fused-тренер (zero autograd)

`examples/pir/fused_trainer.h` — весь тренинг без графа autograd:
предвыделенные буферы (0 malloc на шаг), ручной backward по chain rule
(каждый оператор прокомментирован в коде), forward+backward+клиппинг+Adam
за один вызов `train_step()`. На Эльбрусе даёт ~7× против autograd-пути.

Тонкие места backward (проверены аудитом 2026-07-23):
- скан-BPTT: `dh_t = grad_t + a_{t+1}·dh_{t+1}`, `da_t = dh_t·h_{t-1}`;
- градиент через σ = сумма двух путей (гейтинг входа + гейт скана·λ);
- вход суб-слоя p при backward восстанавливается вычитанием `o_p` из
  накопленного `s_NP` (экономия L·NP·BT·D памяти, цена — FP-шум ~1 ulp);
- GEMM-примитивы: `Y=X·Wᵀ` (fwd), `dX=dY·W`, `dW=dYᵀ·X` — маппятся на
  `sgemm_nt/sgemm/sgemm_tn` → EML BLAS.

## 3. Распределялка: Local SGD по NUMA-узлам

**Схема:** N процессов = N NUMA-узлов (E8C2: 4 узла × 8 ядер). Каждый
процесс пинится `numactl --cpunodebind=k --preferred=k`, тренируется на
своих случайных батчах со своим seed, внутри — EML_MT на 8 OMP-потоков.
Каждые `grad_accum` шагов — **усреднение весов** через `/dev/shm`
(`examples/pir/grad_sync.h`): барьер → сумма → деление → все ранги
продолжают с идентичными весами (сверяется хэшем).

**Почему weight averaging, а не DDP AllReduce градиентов:**
- градиенты нужно гонять каждый шаг; веса — раз в 10 шагов: ×10 меньше
  трафика через медленный межчиповый линк;
- нет NCCL/gloo на Эльбрусе — синхронизация написана на POSIX shm;
- расхождение реплик за 10 шагов при lr~6e-4 мало, усреднение его
  схлопывает (Local SGD / FedAvg-режим).

**Почему процессы, а не 32 потока:** кросс-NUMA доступ роняет GEMM E8C2
с 463 до 330 GFLOPS; node-local процессы масштабируются линейно
(1840 GFLOPS = 92% пика). Плюс правило EML: `cblas_sgemm` из pthread =
SIGILL на E2K, из main-thread с внутренним OMP (`libeml_mt`) — работает.

**Отказоустойчивость:** чекпоинт каждые 500 шагов (сырой float32-дамп
`all_params`), resume через `--load ckpt --start_step N` с линейным
LR-warmup 200 шагов после резюма (Adam-моменты не сохраняются — без
warmup спайк loss). `loginctl enable-linger` обязателен (systemd убивает
процессы при SSH-disconnect); от reboot спасает resume.

## 4. Формат чекпоинта

Сырой little-endian float32, конкатенация параметров в порядке регистрации:

```
W_emb[V,D]
для l in 0..L-1:
    norm1_w[D]
    для p in 0..NP-1: W_gate[D,D], W_value[D,D], W_out[D,D], norm_w[D]
    W_mix[D,D], norm_pir_w[D], norm2_w[D],
    W_ffn1[H,D], W_ffn2[D,H], W_ffn3[H,D]
norm_out_w[D]
W_lm_head[V,D]
```

`H = round_up(D·ffn_mult·2/3, 64)`, ffn_mult=3.5. `base_decay` не
сохраняется — реконструируется из формулы инициализации.
`examples/pir/pir_infer.py` читает этот формат в numpy и генерирует
текст через sentencepiece-декод (сверка: CE numpy ≈ train loss).

## 5. Данные

- **char-level**: любой текстовый файл, vocab 256, токен = байт;
- **BPE**: `prepare_bpe.py` → sentencepiece 16k + `.tokens` (uint32);
  расширение `.tokens` авто-детектится, `--vocab_size` обязателен.

## 6. Реальные результаты

**PIR-342M, char-level, русская Википедия** (E8C2, 4-проц Local SGD,
BPE-эпоха до 2026-04): loss 1.41→1.04 за 800 шагов, 147-158 tok/s
суммарно, связные русские слова в генерации.

**PIR-13.5M, BPE 16k, русская Википедия** (2026-07, после EML-фикса):

| Шаг | Loss | PPL | Генерация (t=0.7) |
|-----|------|-----|-------------------|
| 0 | 9.68 = ln(16000) | 16000 | — |
| 500 | 7.71 | 2233 | обрывки служебных слов |
| 2000 | 6.32 | 555 | «Москва является город — город, на которой был…» |
| 5000 | 5.89 | 362 | «…— коммуна в регионе Соле. Входит в состав кантона…» |

Скорость: 0.46 с/шаг, ~4450 tok/s суммарно (≈360 GFLOPS полезных — 
уровень PyTorch+MKL на 16-ядерном x86; PyTorch на Эльбрус не портирован).

Известное ограничение: это LM на сыром тексте (продолжение текста), не
instruct-ассистент — для диалогового поведения нужен instruct-датасет
вторым этапом.
