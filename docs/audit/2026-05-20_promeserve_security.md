# PromeServe Security & Robustness Audit — 2026-05-20

Цель: ревизия `promeserve/` (HTTP server + Ollama API + MCP client + 9 built-in tools).
В таблице ниже — 21 находка по 6 категориям. Все паттерны атак подтверждены
чтением кода (line refs). PoC не выполнялся.

Severity scale: **CRITICAL** = RCE/полный bypass; **HIGH** = sandbox escape, DoS, leak;
**MED** = частичный bypass, обходной exploit; **LOW** = best-practice / hardening.

## Сводка

**Критические (4):** path traversal #1, execute_python RCE #6, открытый сервер 0.0.0.0 #9, mcp.json injection #17.
**High (8):** bash whitelist #2/#3, curl injection #4/#5, CORS #10, no TLS #11, no rate-limit #15, env leak #16, dispatcher hold #19.

Самое опасное сочетание — **#1 + #17 + #9**: path traversal позволяет писать в `~/.promeserve/mcp.json`,
MCP перезапускается → arbitrary command в child процессе → полный RCE. Сервер слушает 0.0.0.0,
без auth — exploit'абельно с любого LAN-хоста через single HTTP POST на `/api/chat` с tools
с `<tool_call>{"name":"write_file","arguments":{"path":"../../.promeserve/mcp.json",...}}`.

## Рекомендации (приоритет)

1. Bind `127.0.0.1` по умолчанию, добавить `--bind` для остальных.
2. Заменить `sandbox_path()` на `std::filesystem::weakly_canonical` + prefix-check.
3. Все built-in tools: убрать `popen`, использовать `execvp` argv-array (включая sqlite — через C API).
4. Auth token (Bearer) обязательный для `/api/mcp/*` endpoints.
5. JSON parser: depth limit 64.
6. `execute_python` удалить или вынести в отдельный subprocess (firejail/bubblewrap).
7. MCP env передаётся explicit allowlist, не наследуется от parent.
8. Refactor `MCPManager::dispatch_` на `shared_ptr` без long-held lock.
