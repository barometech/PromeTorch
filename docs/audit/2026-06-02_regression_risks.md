## Дополнительные наблюдения (не в основной таблице)

- **OpenBLAS path только в `aten_cpu`, не в `aten_io`/`promeserve`** (CMakeLists.txt:746). `cblas_sgemm` callsites в `torch/io/`, `promeserve/` не получают `PT_USE_OPENBLAS_BLAS` define → даже на E16C идут через TUDA. Заявленный «E16C 2.1 → 5-8 tok/s прорыв» под вопросом для inference path.
- **`__bool__` на 1-element multi-dim** (e.g. `pt.zeros([1,1,1])`): `numel() == 1` → не throws → правильно проходит. OK.
- **`__getitem__` slice path** (line 482-488) не имеет similar bounds-check upgrade — если `t.dim() == 0`, `t.size(0)` падает. Inconsistency с integer path.
- **PromeServe path traversal (security #1)** упомянут в SUMMARY как critical — но `looks_like_path()` в `c2ac3dc` дополнительно расширяет attack surface: имя модели с `/` теперь триггерит file-open. Если HTTP endpoint принимает model name из юзер-input — `--model /etc/shadow.gguf` не откроет (GGUF magic fail), но `fs::exists()` leak'ает существование произвольных путей по timing-каналу.
- **`E2KIntrinsicChecks` НЕ вызывается в CMakeLists** для шапки `if(CMAKE_SYSTEM_PROCESSOR MATCHES "e2k|elbrus")`. Я не вижу `include(cmake/E2KIntrinsicChecks.cmake)` в CMakeLists.txt — только сам файл создан. Если так — auto-detect не активен **нигде**, фича dead на корню (см. R16).
