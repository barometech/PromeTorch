## SUMMARY (≤300 слов)

**Audited 4 файла, 20 пунктов.** Серьёзных багов 1 (CRITICAL), потенциально серьёзных 2 (HIGH), требующих attention 4 (MEDIUM).

**CRITICAL — Q3_K dequant (#3, `gguf_dequant.h:476`):** Функция помечена `Q3_K stub` (line 514), реально содержит 4 независимые bugs: wrap-around `qs[byte_idx % 64]`, неправильные сдвиги scale-unpack (`<< 2` вместо `<< 4`), `hmask[(j+l)%32]` indexing вместо канонического `qi/8 + l/8`, неверная hm-rotation cadence. **При этом `is_type_supported(Q3_K)` возвращает true** (line 585) → callers получают garbage без error. Любой Q3_K_M GGUF (DeepSeek-V2 Q3_K_M, Mistral-Large Q3_K_M) даёт wrong output silently. Это противоречит "Q3 - garbage / stub" пометке audit 2026-05-20 — bug НЕ был исправлен после того audit'а, только повторно подтверждён.

**HIGH — Q5_0/Q5_1 не имеют dequant path (#4, #5):** Q5_0 имеет только scalar GEMV (`cpu_quant_gemv.h:1572`), нет `dequantize_q5_0` в master switch. Q5_1 отсутствует полностью. Загрузка Q5_0 модели в FP16-weights opt-in mode → throw. Q5_1 любой path → throw.

**MEDIUM — RMSNorm eps default 1e-6f vs llama.cpp 1e-5f (#18):** Для моделей без явного `attention.layer_norm_rms_epsilon` в GGUF metadata логиты расходятся. Все top-tier современные GGUF включают ключ, но legacy/custom converts — нет.

**MEDIUM — Q8 SoA4 v4 path (#8):** Bit-exactness vs scalar fallback не валидирован на реальном железе E8C; `597d0a9` claims `working` без cited regression test. Учитывая history `b3db5ce` (1 tok/s broken), нужен mandatory microbench-diff PR-gate.

**MEDIUM — fused triple GEMV (#9):** unguarded assumption `w0->K == w1->K == w2->K` → silent corruption при wrong wiring.

**OK:** Q4_K/Q6_K/Q5_K dequant + AVX2 GEMV, Q8_0, Q8 SoA4 repack + v5 path, RMSNorm formula, SDPA softmax (с минорным `+1e-10` fudge).
