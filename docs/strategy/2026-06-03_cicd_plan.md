# CI/CD: реальное состояние + план улучшения

**HEAD:** `59822c7` · **Дата:** 2026-06-03 · **Повод:** внешний консультант (DeepSeek) заявил «в репозитории нет CI/CD». **Это неверно** — в `.github/workflows/` пять рабочих workflow. Ниже — что они реально делают, где маскируют падения, и реалистичный план.

---

## 1. Существующие workflows: что делает / статус

| Workflow | Триггер | Что делает | Статус |
|---|---|---|---|
| `ci.yml` (CI Build and Test) | push/PR в main | matrix ubuntu+windows: configure → build target `torch_autograd` → ctest | **Прячет ошибки** — ctest под `continue-on-error: true` (стр. 50) |
| `build.yml` (Build) | push/PR в main | 3 job: Linux(gcc), Windows(MSVC), macOS(clang). Linux собирает ядро + 5 examples + гоняет c10/aten тесты | **Прячет ошибки** — examples и тесты под `\|\| true` (стр. 35-39, 43, 47) |
| `elbrus-sim.yml` (Elbrus simulation) | push (paths-фильтр)/PR/dispatch | Docker `debian:bookworm-slim`, TUDA scalar fallback на x86, гоняет `tuda_tests_standalone` + `tuda_tests` | **РАБОТАЕТ честно** — verify-step без `\|\| true`, FAIL валит badge. НЕ настоящий E2K (x86 эмуляция флагов) |
| `wheels.yml` (Build & Publish wheels) | push main / tag v* / PR / dispatch | sdist + cibuildwheel matrix 3 OS × 5 Python = 15 wheels; publish на PyPI/TestPyPI через OIDC Trusted Publishing | **РАБОТАЕТ** — cibuildwheel падает честно. Покрытие меньше заявленного (см. §3) |
| `release.yml` (Publish Release) | tag v* | `git archive` → GitHub Release | Работает, но slipshod: `git archive` вместо `python -m build --sdist` (теряет pyproject normalization, audit #35) |

**Вывод по DeepSeek:** CI есть и нетривиальный (matrix x86/win/mac + wheels + Docker E2K-симуляция + PyPI publish). Реальная проблема не «нет CI», а «зелёный badge ничего не гарантирует» из-за заглушенных падений.

## 3. Покрытие cibuildwheel: что есть / чего нет

**Есть (`wheels.yml:57-58`):** matrix `ubuntu-22.04 × windows-2022 × macos-13` × `cp39..cp313`.

| Платформа | Покрыто? |
|---|---|
| Linux x86_64 (manylinux) | ДА, cp39-cp313 |
| Windows x86_64 | ДА, cp39-cp313 |
| macOS **x86_64** (Intel, macos-13) | ДА |
| macOS **arm64** (Apple Silicon) | **НЕТ** — нет `macos-14` в matrix; `test-skip = ["*-macosx_arm64"]` подтверждает (audit #11) |
| Linux **aarch64** | **НЕТ** — нет ARM-runner, нет QEMU-эмуляции в cibuildwheel |
| **E2K (Эльбрус)** | **НЕТ и не может быть** в облаке (см. §4) |
| **NM Card / NM Quad** | **НЕТ** — проприетарное железо, нет публичного toolchain |
| Python 3.9 | Покрыто, но EOL окт-2025 — мёртвая версия (audit #22) |

ARM/E2K/NM закрываются только через sdist (`build_sdist`) — pip собирает из исходников на целевой машине, prebuilt wheel отсутствует.

## 4. promeserve pytest battery: CI-runner ОТСУТСТВУЕТ

`tests/promeserve/` (`conftest.py`, `test_api_contract.py`, `test_tool_call.py`) — поднимает реальный бинарник promeserve и говорит с ним по HTTP. Включает **security regression** `test_tool_call_path_traversal_blocked` (CRITICAL #1 из security-audit 2026-05-20).

**Ни один workflow её не запускает.** Гоняется только вручную через `scripts/test_promeserve_tools.sh`. Подтверждено audit 2026-06-02 §5. Это самый ценный незакрытый gap: security-регрессия живёт без автоматической проверки.

## 5. План для E2K: почему облако невозможно и что реально

DeepSeek предложил **self-hosted runners на Эльбрусе** — неприменимо:

1. **Сервера заёмные.** `ELBRUS_HOST` — доступ 6 мес; `e16c` — от [коллега]а. Постоянный GitHub-runner на чужом железе вешать нельзя (доступ отзовут, машина не наша).
2. **lcc лицензионный.** MCST `lcc` toolchain в публичный GitHub Actions Docker положить нельзя — нарушение лицензии. Cross-compile x86→E2K в облаке отпадает.
3. **qemu-e2k.** В репозитории НЕТ qemu-e2k (все хиты `qemu*` — это NMCard-эмулятор `aten/src/ATen/nmcard/nmc_programs/`, не E2K). Публичный системный qemu-e2k нестабилен/недоступен.

**Что уже работает вместо этого:** `elbrus-sim.yml` — Docker на x86 с теми же CMake-флагами (PT_USE_TUDA, AVX off, EML mock-stub), ловит macro-коллизии, namespace-ошибки, линковку numa/autograd и прогоняет `tuda_tests`. Это правильный и честный compromise — оставить и расширять.

**Реалистичный E2K-CI:**
- **Tier 1 (есть):** `elbrus-sim.yml` x86-симуляция флагов в облаке — гейт на каждый PR.
- **Tier 2 (добавить):** nightly-скрипт на заёмной машине вручную/по cron — `scripts/build-elbrus.sh` + `test_gguf_inference` + tok/s, результат постит в issue/JOURNAL. НЕ постоянный runner, а отдельный `nightly-e2k.sh` запускаемый по плану пока есть доступ.
- **Tier 3:** просто задокументировать manual build в README (`build-elbrus.sh`, флаги, `loginctl enable-linger`). NM Card/Quad — только manual (железо в ПК юзера).

## 6. Что из DeepSeek неприменимо

- ❌ Self-hosted runner на Эльбрусе — заёмное железо, доступ временный.
- ❌ Cross-compile E2K в облачном Actions — lcc лицензионный, в публичный CI не положить.
- ❌ «У вас нет CI» — фактически неверно, 5 workflow.
- ✅ Применимо: matrix build (уже есть), идея расширить покрытие и добавить строгость.

## 7. Конкретные правки

**P0 — снять маскировку (≈30 мин):**
1. `ci.yml:50` — убрать `continue-on-error: true` с ctest ядра.
2. `build.yml:43,47` — убрать `\|\| true` с `c10_tests` и `aten_tests` (тесты ядра обязаны валить badge).
3. `build.yml:35-39` — examples оставить advisory, но вынести в **отдельный job** `examples (advisory)` с `continue-on-error` на job-уровне, чтобы строгий core-job был чистым сигналом (вместо строчных `\|\| true`).

**P1 — закрыть pytest gap (≈1-2 ч):**
4. Новый job в `ci.yml` (Linux): собрать target `promeserve` → `pip install pytest requests` → `PROMESERVE_BIN=build/promeserve pytest tests/promeserve/ -v`. Без `continue-on-error` — security regression обязана гейтить.

**P2 — покрытие/гигиена (по audit, ≈2-4 ч):**
5. `wheels.yml:57` — добавить `macos-14` (arm64) ИЛИ явно задокументировать x86_64-only.
6. `wheels.yml:58` + pyproject — убрать `cp39` (EOL).
7. `release.yml:14` — `python -m build --sdist` вместо `git archive`.
8. `wheels.yml:67` — поднять/запинить `cibuildwheel` (audit #10); Dependabot.
9. (Опц.) Linux aarch64 wheels через `cibuildwheel` + QEMU (`CIBW_ARCHS_LINUX: aarch64`) — медленно, но возможно в облаке (в отличие от E2K).

**P3 — E2K nightly (≈2-3 ч, когда есть доступ):**
10. `scripts/nightly-e2k.sh` — `build-elbrus.sh` + `test_gguf_inference` + замер tok/s, лог в issue. Запуск вручную/cron на заёмной машине, НЕ GitHub-runner.
